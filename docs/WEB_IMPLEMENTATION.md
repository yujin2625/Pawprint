> 상태: 구현 중. W1(형식 명세), W3(웹 기반) 완료.
> 최종 수정: 2026-10-08
> 설계: [WEB_DESIGN.md](WEB_DESIGN.md)

## 1. 저장소 구성

```
Pawprint/
├─ common/ fabric/ neoforge/      # 모드 (기존)
├─ docs/
│  ├─ FORMAT_PAWPRINT.md          # 청사진 형식 명세 (format 1, 2) — 모드·웹 공용
│  ├─ FORMAT_PAWPACK.md           # 블럭 팩 형식 명세
│  ├─ WEB_DESIGN.md
│  └─ WEB_IMPLEMENTATION.md
└─ web/
   ├─ package.json, vite.config.ts, tsconfig.json
   ├─ src/
   │  ├─ core/          # 프레임워크 무관 로직 (테스트 대상)
   │  │  ├─ format/     #   .pawprint 읽기·쓰기, 공유 문자열, 외부 포맷 변환
   │  │  ├─ pack/       #   .pawpack 읽기, 바닐라 jar → 팩 생성
   │  │  ├─ model/      #   blockstate·모델 해석 (deepslate 감싸기), 상태별 면 목록 캐시
   │  │  ├─ blueprint/  #   편집용 청사진 데이터 구조, 레이어
   │  │  ├─ edit/       #   도구, 브러시, 스탬프, 실행 취소 기록
   │  │  └─ materials/  #   재료 계산 (전체, 레이어별)
   │  ├─ render/        # three.js: 구역 메시, 텍스처 아틀라스, 카메라, 커서 미리보기
   │  ├─ view2d/        # 2D 단면 (Canvas 2D)
   │  ├─ workers/       # 메시 생성 Web Worker
   │  ├─ storage/       # IndexedDB (팩, 프로젝트, 설정)
   │  ├─ platform/      # 웹 / Tauri 차이 (파일 열기·저장, 설치 폴더 탐색)
   │  ├─ i18n/          # 언어 파일 en.json(기본), ko.json, …와 번역 함수
   │  └─ ui/            # Svelte 컴포넌트 (패널, 대화상자, 목록·카드)
   ├─ tests/            # Vitest 단위 테스트, Playwright 화면 테스트
   └─ src-tauri/        # 데스크탑 앱 (8단계에서 추가)
```

- `core`는 브라우저 API와 Svelte에 의존하지 않는다. Node(Vitest)에서 그대로 테스트한다.
- 명세 문서 두 개(`FORMAT_*.md`)를 기준으로 모드(Java)와 웹(TS)을 각각 구현한다.

## 2. 형식 명세 (1단계에서 문서로 확정)

### 2.1 `.pawprint` format 2
- format 1과 같은 zip 구조(`meta.json`, `blueprint.nbt`, `thumbnail.png` 선택)
- `meta.json`에 추가:
  ```json
  "format": 2,
  "layers": [
    {"id": 0, "name": "Default", "color": "#7fb3ff", "visible": true, "locked": false, "parent": null},
    {"id": 1, "name": "Living room", "color": "#ffb347", "visible": true, "locked": false, "parent": 2},
    {"id": 2, "name": "Floor 1", "group": true, "parent": null}
  ],
  "layerOrder": [2, 1, 0],
  "packHint": {"id": "uuid", "name": "Better MC 5 (1.21.1)"}
  ```
- `blueprint.nbt`에 추가: `BlockLayers`(int 배열, `Positions`와 같은 순서), `RemovalLayers`(int 배열, `Removals`와 같은 순서)
- 읽기 규칙: format 1이면 모든 블럭을 레이어 0("Default")으로. 모르는 레이어 번호는 0으로.
- 모드는 레이어를 해석하지 않고 **보존만** 한다(편집·배치 후 저장해도 레이어 정보 유지).

### 2.2 `.pawpack` format 1
- 설계 문서 4.3의 구조. 명세 문서에 각 JSON의 필드, 단위, 필수 여부, 버전 규칙을 적는다.
- `blocks.json` 항목 예:
  ```json
  {"id": "minecraft:oak_stairs",
   "properties": {"facing": ["north","south","west","east"], "half": ["top","bottom"], "shape": ["straight","inner_left","inner_right","outer_left","outer_right"], "waterlogged": ["true","false"]},
   "default": {"facing": "north", "half": "bottom", "shape": "straight", "waterlogged": "false"},
   "item": "minecraft:oak_stairs", "renderLayer": "solid", "tint": null, "tabs": ["minecraft:building_blocks"]}
  ```

## 4. 웹 핵심 구현

### 4.1 블럭 팩
- **불러오기**: zip을 풀어 IndexedDB에 원본 그대로 저장하고, `pack.json`·`blocks.json`·언어·아이콘은 빠른 목록용으로 따로 색인한다.
- **해석**: deepslate의 리소스 인터페이스를 팩 zip 기반으로 구현한다(blockstate·모델·텍스처 조회). 여러 팩을 겹치면 위 팩부터 찾는다.
- **바닐라 jar로 생성**: 사용자가 고른 `<버전>.jar`에서 `assets/minecraft/{blockstates,models,textures}`와 `en_us.json`을 꺼낸다.
  - 한계 1: jar 안에는 **영어 언어 파일만** 있다(다른 언어는 런처가 따로 받음). 웹에서는 영어만 만들고, 데스크탑 앱은 `.minecraft/assets/indexes`와 `objects`에서 다른 언어도 찾는다.
  - 한계 2: 블럭 속성 목록을 blockstate 파일에서 추론하므로 일부 빠질 수 있다(예: 모델에 안 쓰이는 속성). 모드에서 내보낸 팩은 완전하다. 팩 정보에 `"source": "vanilla-jar"`로 표시한다.
- **관리 화면**: 목록/카드 보기, 정보, 이름 변경, 삭제, 기본 팩, 교체, 용량

### 4.2 모델 해석과 캐시
- 블럭 상태 문자열 → deepslate로 blockstate 변형/멀티파트 선택 → 모델 요소 → 면 목록(위치, UV, 텍스처, 틴트 번호, 가림 방향)
- 상태별로 한 번만 계산해 캐시한다. 텍스처는 사용된 것만 아틀라스(2048 또는 4096 크기, 넘치면 여러 장)로 묶는다.
- 애니메이션 텍스처(`.mcmeta`)는 첫 프레임부터 시작해 아틀라스 갱신으로 재생한다.
- 모델이 없는 블럭(상자, 표지판 등), 액체는 대체 표시(아이템 아이콘 상자 또는 색 상자).

### 4.3 편집용 청사진 데이터
- 칸: `Map<위치키, {palette, layer}>`를 16³ 구역별로 나눈다(구역 = 렌더 캐시 단위).
- 팔레트는 상태 문자열 목록(모드와 같은 문자열 형식).
- 레이어: 목록, 순서, 그룹. 한 칸에는 한 레이어.
- 모든 편집은 "변경 묶음"(위치별 이전 값 → 새 값)으로 기록해 실행 취소·다시 실행하고, 바뀐 구역만 렌더에 알린다.

### 4.4 3D 렌더링
- three.js `WebGLRenderer`. 구역별로 불투명/컷아웃/반투명 메시 3개.
- 메시 생성은 Web Worker에서 한다(구역 칸 정보 + 상태별 면 목록 → 정점 배열). 메인 스레드는 업로드만 한다.
- 이웃 칸이 가리는 면은 뺀다. 숨긴 레이어는 메시 생성에서 빠지고, 솔로·흐리게는 셰이더 투명도로 처리한다.
- 커서 미리보기: 놓일 칸·브러시 모양·스탬프를 반투명으로 표시
- 클릭 판정: 구역 칸 데이터로 격자 순회 레이캐스트(메시 레이캐스트보다 빠름)

### 4.5 카메라 (3D)
- 설계 6.2의 조작. 이동 속도는 0.5~200칸/초 범위로 휠 조절, 화면에 잠시 표시
- 키 입력은 우클릭을 누른 동안만 이동에 쓰고, 그 외에는 단축키로 쓴다(겹침 방지).
- `F`: 선택 영역(없으면 전체) 경계 상자에 맞춰 위치·거리 계산

### 4.6 2D 단면
- Canvas 2D로 그린다(선명하고 빠름).
- 칸마다 "보이는 면" 아이콘을 쓴다: 평면도는 위 면, 입면도는 옆면. 상태별로 모델에서 해당 면 텍스처를 뽑아 캐시
- 어니언 스킨: 아래층/위층을 각각 켜고 끄고, 투명도 조절. 위층은 외곽선으로만 그리는 옵션
- 확대/축소(휠), 화면 이동(휠 클릭 드래그), 층 이동(`PgUp/PgDn`, `[ ]`, 슬라이더)

### 4.7 도구
- 공통 인터페이스: 2D/3D 좌표를 받아 미리보기 칸 목록을 만들고, 확정하면 변경 묶음을 낸다.
- 브러시 모양 = 2D 마스크(사각형, 원, 마름모, 사용자 정의). 3D에서는 커서가 닿은 면의 평면에 마스크를 놓는다.
- 채우기는 2D 단면 안에서 같은 블럭으로 이어진 영역. 3D에서는 닿은 면이 있는 층 단면 기준
- 스탬프: 선택 영역 또는 라이브러리 청사진을 스탬프로 저장. 회전·반전 후 찍기

### 4.8 재료
- 모드의 규칙과 같게 센다(문·침대 위쪽 0개, 겹반블럭 2개, 아이템 없는 블럭 따로).
- 전체 / **레이어별** / 선택 영역별 보기. 텍스트 복사(이름 + ID, 세트 표기)
- 이름은 현재 UI 언어 → 영어 → ID 순서

### 4.9 저장
- IndexedDB 저장소: `packs`(원본 zip + 색인), `projects`(청사진 + 썸네일 + 열린 팩 목록), `stamps`, `settings`
- 자동 저장: 편집 후 몇 초 뒤, 창을 닫을 때
- 브라우저 저장 공간 요청(`navigator.storage.persist`)으로 자동 삭제 방지

### 4.10 다국어
- `i18n/en.json`이 기준. 다른 언어는 같은 키를 가진 파일만 추가하면 목록에 나타난다.
- 문장 안 변수는 `{name}` 형식. 복수형은 `Intl.PluralRules`로 처리
- 처음 방문 시 브라우저 언어가 지원 목록에 있으면 그 언어를 제안하되, 기본은 영어

### 4.11 화면 배치 (도킹)
- **처음(W3)부터 모든 패널을 "도킹 가능한 패널"로 만든다.** 패널은 `id`, 제목(i18n 키), 아이콘, Svelte 컴포넌트, 최소 크기, 여러 개 열기 가능 여부를 가진 등록표(`ui/panels.ts`)에 올린다. 패널끼리는 직접 참조하지 않고 공용 상태(store)로만 통신한다. 그래야 나중에 어디로 옮기거나 여러 개 열어도 동작한다.
- W3~W7은 고정 배치(목업의 기본 배치)를 이 등록표로 그린다. W8에서 웹·데스크탑 공통으로 도킹 UI를 켜고, 별도 창은 W9(데스크탑)에서 붙인다.
- 도킹 라이브러리 후보: **dockview**(`dockview-core`, MIT, 프레임워크 무관, 분할·탭·떠 있는 그룹·별도 창 지원). 도입 전에 라이선스·Svelte 연결·Tauri 창에서 별도 창 동작을 확인한다. 안 맞으면 직접 구현(분할 트리 + 탭 그룹)한다.
- 배치는 JSON(분할 트리, 각 칸의 탭 목록·크기, 떠 있는 패널 위치)으로 `settings`에 저장한다. 프리셋도 같은 JSON이다.
- 별도 창(Tauri): 새 `WebviewWindow`에 같은 앱을 "패널 하나만" 모드로 띄우고, 상태는 주 창과 메시지로 맞춘다. 3D 보기를 별도 창에 띄우면 그 창이 자기 WebGL 컨텍스트를 가진다(모델 캐시는 다시 만든다).

## 5. 품질·배포
- 단위 테스트(Vitest): 형식 읽기·쓰기 왕복, 공유 문자열, 외부 포맷, 레이어 규칙, 도구 결과, 재료 계산
- 테스트 데이터: Mojang 텍스처를 저장소에 넣을 수 없으므로 **직접 만든 작은 테스트 팩**(자체 단색 텍스처)을 쓴다.
- 모드 자체 테스트가 만든 `.pawprint` 형식 2 파일로 웹 읽기를 교차 검증한다.
- 화면 테스트(Playwright): 팩 불러오기 → 청사진 열기 → 2D에서 칠하기 → 저장 흐름
- GitHub Actions: 푸시마다 웹 빌드·테스트, `main` 병합 시 GitHub Pages 배포. 데스크탑은 태그를 달면 Tauri 빌드 후 Releases에 올림
